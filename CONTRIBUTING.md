# Contributing

Thanks for helping make a VPN on the PS Vita work well. Bug reports,
measurements from your own setup, translations and code are all welcome.

## Ground rules

This plugin puts every packet of a console people care about through a
kernel module, so a few rules are non-negotiable:

- **Never strand the console.** A problem must end with normal networking,
  never with a console that cannot reach anything. Disconnect restores native
  networking; Lockdown Mode always has its ways out (turn it off, hold L at
  boot, or `ur0:data/vpnturbo/lockdown_off`). The boot guard
  (`user/main.c`) stands the plugin down after two starts that did not finish.
- **Never block in the network stack's path.** Nothing called from the
  stack's driver callbacks waits on a lock; nothing calls into the network
  stack while the console is suspending, waking or has lost its Wi-Fi address
  (`kernel/suspend.c`).
- **Fail closed, never leak.** While traffic is to be held (kill switch,
  Lockdown, a wake), it is dropped, never sent outside the tunnel.
- **No secrets, ever.** Never log, print or commit profile contents or keys.
  No hard-coded servers, networks, addresses or personal data in code, logs
  or docs.
- **Idle means invisible.** With the tunnel off the module must cost nothing
  measurable: no periodic work beyond what an idle wait needs.

## Building

```sh
make            # kernel module + plugins: VitaSDK if $VITASDK is set, otherwise the pinned Docker image
make app        # the LiveArea app (VPK)
make test       # the host tests (no console needed)
make clean
```

Fix any new warnings in the code you touch. The build must stay clean.

## Testing on a Vita

You need HENkaku/Ensō on firmware 3.60–3.74 and
[vitacompanion](https://github.com/devnoname120/vitacompanion)
([my fork](https://github.com/juanjsebgarcia/vitacompanion)), which provides
FTP on :1337 and commands on :1338.

```sh
make deploy VITA_IP=<vita>     # upload the modules and reboot
make log    VITA_IP=<vita>     # fetch kernel.log, shell.log and app.log
```

Install the app's VPK with VitaShell. If a change misbehaves, **hold L while
the Vita boots** to skip all plugins, then fix `ur0:tai/config.txt` or the
module over FTP.

When you report a result, include the firmware, the Vita model, how the
tunnel's server is reached (home server on the LAN, a remote server), the
relevant log lines, and how you measured.

**Redact the logs before you post them.** They can record your Wi-Fi and
tunnel addresses, your server's address and the names of your profiles.
Replace them with placeholders such as `<server>`, `<lan-ip>`. Never post a
profile (`.conf`) or its QR code: it contains your private key.

## Translations

The app's strings live in `app/src/strings_en.def` and `app/src/lang/*.def`
(`app/TRANSLATIONS.md`); the Settings page and quick-menu strings are
generated by `tools/gen_i18n.py` into `settings_app/i18n_table.h` (run it after a
change; it checks the widths that fit). The HUD (`kernel/hud_i18n.c`) is drawn
with an ASCII bitmap font, so it only carries Latin-script translations; other
languages show English there.

## Pull requests

- One logical change per PR, with a clear description of what changed and how
  you tested it (on hardware if it touches the kernel module).
- Commit messages in the existing style: `vpn: <what changed>`,
  `docs: <what changed>`.
- By contributing you agree that your contribution is licensed under the MIT
  licence of this project.
